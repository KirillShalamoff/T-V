## 2. Конвейер

Всё находится в `funnylex.py`.

1. **Парсер регулярок** — рекурсивный спуск в AST (`CharSet`, `Concat`, `Alt`, `Star`, `Plus`, `Opt`, `Epsilon`);
   классы символов сразу раскрываются в множества ASCII-кодов.
2. **НКА Томпсона** — у каждого узла AST фрагмент «вход → выход»; объединённый НКА получает
   новый старт с ε-переходами во все 34 фрагмента, выход фрагмента *i* помечен токеном *i*.
3. **ДКА подмножествами** — ε-замыкания + move по каждому из 128 ASCII-символов;
   пустое множество — явная **ловушка**. Метка принимающего состояния — токен с минимальным индексом
   среди принимающих НКА-состояний множества (так ключевые слова побеждают `IDENT`).
4. **Хопкрофт** — начальное разбиение: {непринимающие} + отдельный блок для **каждого токена**
   (иначе склеились бы, например, `KW_IF` и `IDENT`); дробление сплиттерами из рабочего множества,
   при дроблении блока вне W в W кладётся меньшая половина. Итоговые состояния перенумерованы BFS от старта.
5. **Экспорт** — столбцы таблицы сжаты в классы эквивалентности символов (одинаковые столбцы = один класс).

## 3. Размер автоматов

| Автомат | Состояний |
|---|---|
| НКА (Томпсон) | 189 |
| ДКА (построение подмножеств), включая ловушку | 81 |
| Минимальный ДКА (Хопкрофт), включая ловушку | **78** |

Алфавит: 128 ASCII + 1 символ `OTHER` = 129 символов → **41 класс** символов.
Таблица переходов: 78 × 41 = 3198 ячеек вместо 78 × 129 = 10062.

Минимизация склеила 3 пары состояний — типичные «хвосты» конструкции Томпсона, где после первой
итерации `*` множество НКА-состояний другое, но поведение то же:

| Токен | Состояние после | эквивалентно состоянию после |
|---|---|---|
| `INT` | `1` | `10` (цикл `[0-9]*`) |
| `IDENT` | `A` | `A0` (цикл `[A-Za-z0-9_]*`) |
| `COMMENT` | `//` | `//x` (цикл `[^\r\n]*`) |

Минимальность проверяется независимо алгоритмом Мура (`moore_class_count`): число классов
эквивалентности = 78 = числу состояний, и для исходного ДКА оно тоже 78.

## 4. Ловушка

* Состояние `1` в `build/dfa.json` (`"trap": 1`): непринимающее, все 41 переход ведут в себя.
* Символ вне ASCII отображается в класс `other_class` (40), и из **любого** состояния по нему переход в ловушку.
* ASCII-символы без переходов из старта (класс `c0`: управляющие кроме `\t \n \r`, `! " # $ % & ' . ? @ \ ^ ` | ~`, DEL)
  тоже ведут в ловушку; `!` выводит из неё только в паре `!=`.
* Лексер (maximal munch) идёт по ДКА до ловушки, запоминая последнее принимающее состояние.
  Если его не было — выдаётся `TRAP` с первым символом, и разбор продолжается со следующего.

  эквивалентность `re.fullmatch` ≡ НКА ≡ ДКА ≡ min ДКА для каждой регулярки и для объединённого автомата
  (полный перебор строк длины ≤ 3 над 38-символьным алфавитом + 3000 случайных строк);
  минимальность (Мур); полнота таблицы и свойства ловушки; приоритет ключевых слов;
  совпадение сжатой таблицы с полной; round-trip JSON; ошибки парсера регулярок и спецификации.
